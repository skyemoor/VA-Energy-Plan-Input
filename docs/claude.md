# Work Standards
 
## Workflow
1. **Explore:** Search the codebase for existing patterns before proposing solutions. Do not read the entire repo blindly; scope your file search tightly.
2. **Identify and Evaluate Alternatives:** Identify and give short explanation of alternatives and their tradeoffs if multiple viable solutions exist. If one stands out as the apparent optimal solution, recommend it.
3. **Plan:**Output a concise implementation plan with explicit steps and any unresolved questions. Wait for confirmation. Once confirmed, Capture any rationale about the choice in the appropriate scenario technical notes. 
4. **Implement:** Write clean, modular code following existing software_engineering_standards.md .
5. **Verify:** Run relevant tests or linter checks to validate changes, devising a new test first wherever no existing test already covers the changed behavior.

## Rules
- Keep explanations brief and direct.
- When writing/modifying code, always first read and follow `software_engineering_standards.md`. Do not read it otherwise, to save cognitive capacity.
- Ask for clarification if a task specification is ambiguous.
